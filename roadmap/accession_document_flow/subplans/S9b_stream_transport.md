# S9b — Streaming Acquisition Transport

## Owner and status

- Owning stage in [S9](S9_acquisition.md): bounded HTTP body transfer.
- Status: file-backed HTTP streaming and body-free broker RPC are implemented; the S9
  runner that binds them to acquisition attempts is not.
- Depends on: [S9a work orders](S9a_target_adapter.md), S4 broker lifecycle.

## Current tracked-code audit (2026-10-10)

- **Status: lower-layer streaming is implemented, S9 composition is not.** The additive `SecHttpClient.stream_to_file()` writes bounded decoded chunks atomically and leaves `get_bytes()` unchanged. `SecBroker.stream_to_file()` sends only metadata and a managed path over IPC.
- **Evidence:** [`infra/sec_http/streaming.py`](../../../edgar_sec/infra/sec_http/streaming.py), [`infra/broker/sec_broker.py`](../../../edgar_sec/infra/broker/sec_broker.py), and their mirrored tests cover redirects, byte limits, cleanup, typed 404, and body-free IPC.
- **Next step:** compose the broker result with the S9 selected-body lifecycle and bounded engine extractor; the runner must not route large responses through `get_bytes()`.

## Objective

Transfer multi-megabyte filing bodies without buffering them in the broker's parent process or returning payload bytes over process IPC.

## Models

```python
@dataclass(frozen=True, slots=True)
class StagedBodyRef:
    staging_id: str
    path: Path
    origin: Literal["http_response", "bundle_child"]
    source_url: str | None
    final_url: str | None
    body_sha256: str
    body_size: int
    content_type: str | None
    content_encoding: str | None
    derived_from_sha256: str | None

@dataclass(frozen=True, slots=True)
class StreamFailure:
    target_id: str
    code: Literal[
        "http_not_found", "http_error", "timeout", "transport_error",
        "response_too_large", "unsafe_redirect", "empty_body",
    ]
    retryable: bool
    detail: str

StreamResult = StagedBodyRef | StreamFailure
```

## Interface and flow

```python
SecHttpClient.stream_to_file(
    url: str,
    destination: Path,
    *,
    max_response_bytes: int,
    validate_redirect: Callable[[str], None],
) -> StreamResult

SecBroker.stream_to_file(
    url: str,
    *,
    max_response_bytes: int,
    accession_cik: str | int,
    accession_number: str,
    staging_root: Path | None = None,
) -> StreamedFileResult
```

The broker owns the HTTP session, retry policy, rate limiter, and failure ledger. The
HTTP client writes decoded chunks to a sibling temporary file, hashes and counts those
bytes, and atomically adopts only a complete non-empty response. `Content-Length` is
an early rejection hint; the streamed byte count is the enforcement check.

On a limit breach, stop reading, close the response, delete the partial file, and return `response_too_large`; never return a truncated body. Redirect URLs must satisfy the S9a archive-locator contract for the work target's accession directory before bytes are accepted. The final URL and content headers are recorded for provenance.

The host policy is exact `www.sec.gov`. An HTTP 404 returns
`StreamFailure(code="http_not_found")`. S9 maps it to acquisition status `failed`, not
`not_filed`; only successful full-bundle parsing can establish that a requested sequence
is absent.

The transport returns a small `StagedBodyRef`, not bytes. A child process opens the managed path for extraction and returns only result metadata and digests. Path names are generated by the staging owner, not from accession, URL, or filing data. Partial files are removed on error; successfully acquired slot bodies remain staged through S10 and until S11 publishes their Parquet rows or the run is explicitly discarded. See the [acquisition lifecycle](document_acquisition/lifecycle.md).

Worker concurrency is derived with `derive_resources()` and `auto_worker_count()`; each child receives at most one active body/extraction task and the submitted queue is bounded. The maximum body size and worker memory estimate are settings/measurements, not duplicated numeric limits in S9 code.

## Tests

- A fake streaming transport feeds chunks across the byte limit and verifies early abort, partial-file removal, and typed failure.
- Missing `Content-Length` cannot bypass the accumulated-size limit; a compressed body is bounded after decoding.
- Direct-target and bundle HTTP 404 responses produce `http_not_found` failures and never `not_filed` outcomes.
- Successful transfer has a byte-identical digest, correct final URL, and no payload bytes in the broker result or worker-to-coordinator IPC.
- Redirects outside `www.sec.gov` or the target accession directory fail before accepting the body.
- In-flight body count and worker count remain within the derived resource budget.
- Staging cleanup handles success, transport failure, timeout, process failure, and cancellation.

## Acceptance criteria

Payload size is bounded during transfer, process handoff is by managed path and metadata, and normal acquisition does not materialize an entire response in the broker parent or coordinator. Fixture capture is the only path that retains source bodies after the downstream run.
