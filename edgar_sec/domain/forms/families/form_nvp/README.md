# form_nvp

Domain models for Form N-VP, the registration form for variable
annuity and variable life separate accounts under the summary
framework, and its N-VP/A amendments, N-VPFS financial-statements
filings, and N-VPFS/A amendments: the family's processing profile
and section taxonomy over the shared text and table-geometry
machinery. The section vocabulary is the one filed specimens
evidence: the notice documents' prescribed key-information
sequence, and the financial-statements block the N-VPFS filings
carry.

## Contracts

- **Text path**: the profile offers RAW and RENDER_TO_TXT with text
  preferred; N-VP/A, N-VPFS, and N-VPFS/A resolve to the same
  catalog entry through the family alias.
- **Section resolution**: with the profile's sections flag set,
  normalize and the shared analysis path resolve sections from the
  catalog entry's taxonomy items, in filed order.
- **Report projection**: filings of the family project as
  FormNVPReport.

## Deliberate gaps

- **No XBRL leg**: no specimen in the census carries an XBRL
  instance or an inline flag, so the profile claims no XBRL
  support.
- **No exhibit model**: exhibits ride the generic path; the
  family's exhibit vocabulary was not modelled.
- **No notes-sequence flag**: notes detection was not measured for
  this family; the notes block resolves as a taxonomy section.
- **No bespoke review analyzer**: the shared analysis path reads
  the catalog entry directly.
- **Supplements stay sparse**: N-VP/A supplements that restate no
  key-information section resolve few or no sections; that absence
  is the filed shape, not a detection failure.
