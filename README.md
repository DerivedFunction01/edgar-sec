# edgar-sec

High-throughput, memory-safe SEC EDGAR extraction engine and pipeline. It
transforms SEC submissions and filing disclosures into clean, versioned,
queryable columnar datasets (Parquet / Arrow / DuckDB). This README is the
onboarding gateway: it points at the modules and documents that own each
fact rather than restating them. `pyproject.toml` is the package
declaration of record — name, dependencies, Python floor, console script,
and wheel contents are all read from there.

## Start here

- [AGENTS.md](AGENTS.md) is the binding engineering contract. Where any
  README and AGENTS.md disagree, AGENTS.md wins — except scanner rules,
  whose authority is [docs/scanners.md](docs/scanners.md).
- Every package under `edgar_sec/` owns a `README.md` in the Purpose /
  Contracts / Deliberate gaps shape. Package facts live there, not here;
  follow the roster links below.
- Resource budgets are derived, never hardcoded. The guarantees and the
  scanners that enforce them are stated in AGENTS.md (Memory & Performance
  Non-Regression Guarantees).

## Architecture

from layers below it, never above, and the `layer-boundary` scanner in the
gate enforces the graph. The layer rules are normative in AGENTS.md
(Architectural Layers & Boundaries).

## The gate

`check.py` is the unified quality gate: ruff format, ruff lint, the
registered policy scanners, and pytest. The default run is change-aware —
an AST reverse-dependency lineage over the git changes selects the
affected tests, and prose-only edits (docstrings, comments, markdown)
select none. The mode flags (`--fix`, `--fast`, `--scan`, `--test`,
`--package`) are mutually exclusive. Run it from the repository root:

```bash
.venv/bin/python check.py            # change-aware gate (the default)
.venv/bin/python check.py --fast     # format, lint, scanners; no tests
.venv/bin/python check.py --explain  # show detected changes and test lineage
.venv/bin/python check.py --all      # full suite; a proof run, not the default gate
```

## Setup

Requires the Python floor declared in `pyproject.toml`. Build the venv
from that single dependency source, and generate the documented
environment configuration:

```bash
python3 init_venv.py
python -c "from edgar_sec.foundation.runtime.settings import render_dotenv; print(render_dotenv())" > .env
```

Run every command from the repository root. Mutable workspace data
(artifacts, uploads, caches) roots at the working directory by default;
the `workspace.root` setting (environment name `WORKSPACE_ROOT`,
registered in `edgar_sec/foundation/runtime/settings/paths.py`) names a
different root. The version of record is `__version__` in
`edgar_sec/__init__.py`, wired through `[tool.hatch.version]`.

To install the package itself into another environment, use uv with a
built wheel or a local checkout:

```bash
uv pip install /path/to/edgar-sec
```

The wheel ships the `edgar_sec` package without the tools layer; the
exclusions are declared in `[tool.hatch.build.targets.wheel]` in
`pyproject.toml`.

## Where artifacts live

Each pipeline owns its artifact paths in its `paths.py` module and
documents them in its package README under `## Artifact layout`; the
roots come from the settings providers under
`edgar_sec/foundation/runtime/settings/`. Merge and publication contracts
belong to the pipeline that owns them — for example, metadata sync's
contract is stated in
[its package README](edgar_sec/pipelines/metadata_sync/README.md).
Nothing about a pipeline's layout or semantics is restated here.

## Venue discipline

While Colab High-RAM sessions are live, gates and other compute run on
the fleet, not locally: local work is authoring and orchestration only,
and execution rides the runner funnel (`bin/colab-run`) with caller
attribution. Gates scope to the change and shard across the available
sessions — the binding statement is the Supervision rules block in
AGENTS.md. The venue contract itself (lease lifecycle, session rules,
sync discipline) is owned by `pipeline/venue/AGENTS.md` in the
workspace's `supreme-octo-robot` repository.

## Tests

The test tree mirrors the source tree; every test directory is a package,
and fixture access goes through `tests.support`. The conventions are
normative in AGENTS.md (Testing & Fixtures). Never run `pytest` over the
whole `tests/` tree as a gate — that is `check.py --all`, a proof run.
